# №TBD — `Result[<псевдоним указателя>, <сумма с нагрузкой>]` инстанцируется как `Result[int, str]`

**Замер 2026-09-13 18:30**, окно плана 01, пакет `nova-duckdb`. Найдено при написании
эффект-семейства `Db`: операция `query(conn, sql) -> Result[CResultHandle, DuckError]`
не собирается, хотя `nova check` печатает `ok:`.

Команда на каждую пробу (файл кладётся в `src/` временно, с расширением `.nv`):

```sh
./nova.sh test src/
```

## Таблица: ось — ПАРА, а не любая из половин

| проба | `Result[Ok, Err]` | исход |
|---|---|---|
| `a_green_alias_plus_str` | `Result[CResultHandle, str]` — псевдоним + обычная строка | ✅ `PASS` |
| `d_green_int_plus_sum` | `Result[int, DuckError]` — обычный тип + сумма | ✅ `PASS` |
| `b_red_alias_plus_sum` | `Result[CResultHandle, DuckError]` — **обе половины сразу** | ❌ `CC-FAIL` |
| `c_green_newtype_record` | `Result[ResultRef, DuckError]`, где `ResultRef` — **newtype-запись** вокруг той же ручки | ✅ `PASS` |

**Ни одна половина не виновата поодиночке**, и это то, что сетка показала, а рассуждение
не показало бы: псевдоним указателя живёт с обычной ошибкой, сумма живёт с обычным
успехом, падает только пара. Эффект для воспроизведения НЕ НУЖЕН — проба `b` это
свободная функция.

## Улика прямо в сгенерированном C

```
error: passing 'Nova_DuckError *' to parameter of incompatible type 'nova_str'
  return nova_make_NovaRes_nova_int_nova_str_Err(nova_make_DuckError_Query(...));
                         ^^^^^^^^^^^^^^^^^^^^^
error: passing 'nova_str' to parameter of incompatible type 'Nova_DuckError *'
  m = Nova_DuckError_method_message(e);
```

Имя инстанцированного типа — **`NovaRes_nova_int_nova_str`**, то есть
`Result[int, str]`. Оба аргумента свёрнуты к ПРЕДСТАВЛЕНИЯМ: `CResultHandle` (алиас
`*()`) к `nova_int`, `DuckError` (сумма, у всех вариантов нагрузка `str`) к `nova_str`.
Дальше конструктор и разбор согласованы с этим свёрнутым типом, а места вызова — с
объявленным, и C ловит несовпадение с обеих сторон сразу.

**`nova check` на это молчит.** Третий случай за сутки, когда зелёный `check` не
свидетельствует о собираемости (см. также №1082 и №1077), и первый, где причина —
мономорфизация, а не разрешение имён.

## Обход, применённый здесь — и он ЛУЧШЕ обходимого

Ручки в эффекте объявлены **newtype-записями** (`ResultRef { ro h CResultHandle }`), а
не голыми псевдонимами. Проба `c` показывает, что этого достаточно.

Обход не компромисс: D456 п.5 требует, чтобы дескриптор был **именованным типом**, а не
сырым числом или указателем, — newtype ровно это и есть. Псевдоним `*()` удовлетворял
правилу по букве (имя есть) и не по существу (представление то же, и мономорфизация это
видит). Так что правка чинит и форму, и сборку.
